# 中文代码注释翻译

## 目标和边界

把目标范围内已有注释中的英文或其他自然语言翻译成准确、自然、可维护的中文，同时保持代码行为、注释位置、文档结构、标签、链接和技术标识不变。

- 只处理注释、文档字符串、JSDoc/Javadoc/Doxygen/XML 文档和注释中的自然语言。
- 不翻译变量名、函数名、类名、API 名称、协议名、命令、代码片段、正则表达式、链接、占位符或字符串字面量；除非用户明确要求修改这些内容。
- 不新增 why 解释、不补缺失注释、不修复业务逻辑、不重构代码、不改变日志和错误文本。
- 混合语言注释只翻译其中的非中文自然语言，已有中文和必要英文术语继续保留。
- 跳过生成文件、依赖目录、压缩文件和二进制文件，除非用户明确指定。

## 工作流程

1. **先检查 Context7 MCP**：查看当前 Codex 会话是否有可用的 Context7。若目标注释包含版本敏感的库、框架或 API 术语，优先查询匹配版本的权威文档确认术语含义；不可用时回退到仓库源码、锁文件和项目词汇，不要阻塞翻译。
2. **确认范围和语言**：识别目标文件、注释语法、项目术语表、语言版本和文档工具；建立待翻译注释清单，排除字符串和代码标识符。
3. **逐条翻译**：按原注释顺序翻译每一条，保留原有语气、信息量、列表、表格、Markdown、HTML/XML 标签、JSDoc 标签和代码围栏；不要借翻译机会补充原文没有的事实。
4. **处理术语和歧义**：优先使用项目已有译法；没有约定时保留必要英文术语并在首次出现处给出简短中文释义。无法确认技术含义时标记“需要业务确认”，不要猜测。
5. **验证**：检查注释仍使用目标语言合法语法，标签和占位符数量未改变，链接和代码片段未损坏；至少运行 `git diff --check`，确认差异只涉及注释文本。

## 翻译质量要求

- 以语义准确为先，不逐词硬译；同一术语在同一文件或模块中保持一致。
- 保留 `@param`、`@return`、`@throws`、`<param>`、`Args:` 等结构，只翻译其说明文本。
- 保留大小写、标识符、版本号、路径、命令和示例代码；中文标点不得进入代码片段或标签属性。
- 原文事实不完整或表述含糊时，不擅自扩写为 why 解释；将事实性疑点列入交付摘要。

## 调用示例

```text
请使用 chinese-code-comment-translate，把 src/legacy.py 中已有英文注释和 docstring 翻译成中文。
不要新增注释，不要翻译函数名、API 名称、字符串字面量或代码示例，只修改注释文本。
```

```text
请使用 chinese-code-comment-translate，翻译 services/ 中的 Javadoc 和 XML 文档；保留所有 @param、@return、<param> 标签及其参数名，只翻译标签里的说明。
```

## 完成前自检

- 每一条目标注释都已检查，英文或其他自然语言已翻译，原有中文没有被覆盖。
- 没有修改代码、字符串、标识符、链接、代码围栏、标签结构或文档格式。
- 没有把翻译任务扩展成补注释、解释 why、重构或业务修复。
- 术语、占位符和版本信息保持准确；不确定之处已明确记录。
